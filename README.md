# bare_app

GUI-приложение для OdroidLinux SDK на LVGL. Первая цель — ODROID-GO Advance:
экран, кнопки и стик. Архитектура рассчитана на добавление плат и оборудования
и на замену LVGL другим тулкитом: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

Репозиторий подключается к SDK сабмодулем `apps/bare_app`. Сабмодули внутри:
LVGL (v9.6.0) — `third_party/lvgl`, doomgeneric — `ports/doom/doomgeneric` (нужен
только для `GAME_DOOM`):

```sh
git submodule update --init --recursive apps/bare_app      # из корня SDK
```

## Лицензии

Всё, кроме каталога [`ports/doom/`](ports/doom/), — код bare_app. В `ports/doom/` лежит
Doom под GPLv2: из него собирается отдельная программа `bare_app_doom`, которая
в `bare_app` не линкуется. bare_app запускает её и обменивается с ней только кадрами
и событиями геймпада. Так же устроены Герои III: клиент VCMI (GPLv2) собирает пакет
`vcmi` SDK со своим патчем, а здесь только протокол `src/games/game_ipc.h`.
И Half-Life: движок Xash3D FWGS (GPLv3) с платформой bare_app собирает пакет
`xash3d-fwgs` SDK, код игры (лицензия Valve SDK) — пакет `hlsdk-portable`.

## Главный экран

Игры идут в ряд крупными квадратными плитками: первой — запущенная последней, за ней
остальные в порядке запусков, ещё не запускавшиеся — в конце, в порядке сборки.
Порядок хранится в файле настроек (`recent=`: до 16 коротких ключей игр). Над рядом —
название выбранной,
под ним — круглые кнопки остальных экранов (тест ввода, USB-диск, настройки,
выключение), внизу — что сделают X и A. Влево и вправо — по ряду, вверх и вниз — между
рядами. Сверху посередине — время (если часы выставлены), справа — громкость, Wi-Fi и
батарея: заливка по уровню с процентом внутри, белая, с 20 % жёлтая, при зарядке
зелёная (с молнией); с 10 % без зарядки — тёмная с красными цифрами.

Плитка показывает обложку игры — PNG `cover.png` в её каталоге: `/games/heroes3`,
`/games/halflife`, `/games/doom`, `/games/<игра>/` у Windows-игр (или файл из ключа
`cover` в `wine.ini`), у игр из `game.ini` — ключ `cover` или `cover.png` рядом.
Квадратная картинка любого размера, обрезается по плитке (7×7 клеток сетки: 140×140 на
OGA, 210×210 на GO Ultra).
Без обложки плитка — название игры на цветном фоне. Игра, которой не хватает
файлов, затемнена с пометкой «не установлена», свёрнутая — со значком паузы.

В любой игре F5 сворачивает её (Героев III на GO Ultra — F1): процесс игры
останавливается (SIGSTOP), на экране меню bare_app, у пункта игры значок паузы. Та же
кнопка на любом экране или пункт этой игры в меню разворачивают её с того же места. Пока игра свёрнута, пункт другой игры (или экранов «USB-диск»,
«Слои») спрашивает: отменить или закрыть свёрнутую игру и запустить выбранную.
Удержание F6 в игре 2 секунды закрывает игру и возвращает в меню; в меню удержание
F6 закрывает всё приложение.

### Управление игры

X на плитке игры открывает её управление: строка на каждую кнопку устройства, которую
получает игра, и справа — какой кнопкой она будет для игры. Влево/вправо (или A)
перебирают кнопки и «—» (ничего), X возвращает кнопку как было, последняя строка
возвращает все. Сверху — подсказка игры, что делают её кнопки. Изменения действуют с
следующего нажатия, в том числе в свёрнутой игре (F5 → X на её плитке → B → A).
Под кнопками — инверсия осей стиков, отдельно по X и по Y для каждого стика, который
есть у устройства («Левый стик: инверсия Y» — Вкл./Выкл.; A, влево или вправо
переключают, X — выключает): игра получает ось с обратным знаком, а направления,
которые делает левый стик (его «крестовина»), меняются вместе с осью. Последняя
строка возвращает всё управление игры как было.
С датчиком движения в сборке (`INPUT_IMU`) ещё две строки: «Прицел гироскопом»
(Вкл./Выкл.; X — как задумано игрой: по умолчанию включён у Doom, Half-Life и
DOOM 3, выключен у игр с курсором) и «Чувствительность гироскопа» (0.2…8.0×,
по умолчанию 2.0×: обзор поворачивается вдвое больше консоли; влево/вправо по 0.1).
Хранятся в файле настроек по игре: `controls.<ключ игры>=a=b,b=a,x=-,ly=invert,gyro=on,gyrosens=2.5`
(только отличающиеся кнопки, инвертированные оси `lx`, `ly`, `rx`, `ry` и гироскоп). Кнопки,
которые bare_app оставляет себе (питание, громкость, F6, кнопка сворачивания игры,
L2/R2 у игр, где они — громкость), в списке нет; направления левого стика как кнопки
не переназначаются — меняются кнопки устройства.

### Низкий заряд в игре

Во время игры (экран игры, не свёрнутой) при заряде 15 % и меньше без зарядки сверху
на 6 секунд появляется красное предупреждение «Батарея разряжена: N % / Подключите
зарядку» — при запуске или возвращении в игру и затем на 10, 5, 3 и 1 %. С 5 % в
правом верхнем углу остаётся батарея с процентом — там же и такая же, как в строке
статуса (поверх графика кадров монитора системы, если он показан). Зарядка убирает всё и начинает отсчёт заново. Обычное уведомление
приложения о низком заряде над игрой не показывается. На ПК батарею можно
изобразить: `BARE_APP_SIM_BATTERY=<каталог>` с файлами `capacity` и `status`, как в
`/sys/class/power_supply/*`; подключённые клавиатуру, мышь и датчик движения (значок USB
в строке статуса) — `BARE_APP_SIM_DEVICES=<маска INPUT_DEV_*>` (7 — всё, при
скриптовом вводе со stdin).

## Монитор системы

Удержание F5 (0,6 с) на любом экране и в любой игре показывает поверх всего монитор
системы (символ `SYSMON` в Kconfig, включён по умолчанию). Повторное удержание над
игрой оставляет от него только маленькую панель с графиком кадров в правом верхнем
углу, третье — прячет всё (без игры второе удержание сразу прячет монитор). Игра под
ним продолжает идти. Раз в секунду, пока монитор открыт:

- загрузка и частота каждого кластера CPU (на GO Ultra — A53 ×2 и A73 ×4), полоска
  на каждое ядро;
- частота GPU, занятая память (и подкачка, если есть);
- температуры (зоны `thermal`; зона батареи не показывается: без термистора драйвер
  отдаёт постоянное значение, у rk818 на GO Ultra — 20 °C);
- батарея: заряд, напряжение, ток и мощность (плюс — в батарею, минус — из неё);
- каждый диск (eMMC, SD, USB): полоска и процент — занятое место на его разделах
  (как в `df`, без `/boot`), чтение и запись в МБ/с, ниже свободное место по
  разделам;
- пока игра на экране — её кадры в секунду (кадры, которые она присылает в слой
  видео) и график времени кадров за последние 10 секунд (см. ниже);
- bare_app и запущенная им игра: CPU (в процентах одного ядра, потоки
  складываются), память.

Монитор всегда на английском, какой бы язык ни был выбран.

### График кадров

Столбик на каждый пиксель ширины: кадр занимает время от предыдущего кадра до себя
и высоту по тому, сколько он шёл (верх графика — 100 мс, дольше — обрезается), так что
подвисание — широкий высокий блок. Синие кадры — обычные, оранжевые — рывки: кадр
шёл вдвое дольше медианы и дольше 25 мс. Линии — 60 и 30 кадров в секунду. Над
графиком: кадры за последнюю секунду, 99-й процентиль времени кадра, самый долгий
кадр и число рывков за 10 секунд. Время берётся в момент, когда bare_app выводит
кадр игры (`core/frametimes.c`), поэтому это то, что видно на экране.

`BARE_APP_SYSMON=full` или `frames` показывает монитор (весь или только график) сразу
при запуске — для замеров, когда F5 не удержать (на GO Ultra кнопку нельзя удержать
программно). С переменной окружения `BARE_APP_FRAME_STATS=1` то же самое раз в 10 секунд пишется в
лог (`view: frames: ... hitches`), с `BARE_APP_FRAME_STATS=2` — ещё и каждый кадр дольше
60 мс с его временем (`CLOCK_MONOTONIC`, для сопоставления с профилем), а при выходе из игры в лог всегда пишется, сколько
кадров шло дольше 50 и 100 мс и самый долгий из них.

Короткое нажатие F5 работает как раньше (свернуть игру, у Героев на GO Ultra —
отмена или конец хода), но срабатывает при отпускании. Данные берутся из `/proc` и
`/sys` без таблиц платформы, поэтому монитор работает и на ПК
(`services/sysmon.c`).

## Doom

Пункт «Doom» в главном меню (символ `GAME_DOOM` в Kconfig, включён в `oga_defconfig`
и `pc_defconfig`). Движок [doomgeneric](https://github.com/ozkl/doomgeneric) (GPLv2)
собирается из `ports/doom/` в отдельную программу `bare_app_doom`, которая ставится рядом
с `bare_app`. Движок хранит состояние в глобальных переменных и выходит через `exit()`,
поэтому на каждую игру запускается новый процесс. Падение игры не роняет приложение,
а лицензия GPL не распространяется на `bare_app`.

- Игра рисует кадры 320×200, растянутые до 4:3 по высоте экрана, в общую память
  (memfd, тройной буфер без блокировок). Приложение кладёт их в видеослой (на OGA —
  плоскость DRM). Кнопки идут в игру через сокет (`src/games/game_ipc.h`).
- Нужен видеослой: DRM на плате, `pc-mem` на ПК. В окне SDL и на fbdev экран покажет
  сообщение.
- Звуковые эффекты игра выводит сама (`ports/doom/doom_sound.c`, ALSA без SDL) на
  устройство из таблицы платформы (`-pcm /dev/snd/pcmC0D0p` на OGA). На ПК игра
  запускается с `-nosound`. Музыки и сети нет.
- IWAD: первый найденный в `GAME_DOOM_GAME` (`/games/doom`, раздел FAT32 SDK, туда
  копируют с ПК) из `doom2.wad`, `plutonia.wad`, `tnt.wad`, `doom.wad`, `freedoom2.wad`,
  `freedoom1.wad`, `doom1.wad`, иначе `GAME_DOOM_WAD` (по умолчанию
  `/usr/share/games/doom/doom1.wad`); во время работы его можно заменить через
  `BARE_APP_DOOM_WAD`. Настройки и сохранения хранятся в `GAME_DOOM_DIR`
  (`~/.local/share/bare_app/doom`, в `oga_defconfig` — `/data/doom`).
- Из игры в меню приложения возвращают удержание F6 или пункт Quit Game в меню Doom,
  F5 сворачивает игру. Если игра не запустилась или упала, экран покажет причину.

| Кнопка | В игре | В меню Doom |
|---|---|---|
| крестовина / стик | ходьба, поворот | выбор пункта |
| A | огонь | Enter («y» в вопросе да/нет) |
| B | использовать (двери, кнопки) | назад |
| X | бег (удерживать) | |
| Y | следующее оружие | |
| L1 / R1 | шаг влево / вправо | |
| Select | карта | |
| L2 / R2 | громкость тише / громче | |
| F1 (Start) | меню Doom | закрыть |
| F2 / F3 | сохранить / загрузить | |
| F4 | пауза | |
| F5 | свернуть игру | |
| F5 (удерживать) | монитор системы | |
| F6 (удерживать 2 с) | выйти из игры в меню bare_app | |

На ПК (shareware-WAD можно взять в пакете `doom1-wad` SDK):

```sh
echo "wait:500 a wait:3000 f6" | BARE_APP_DOOM_WAD=doom1.wad BARE_APP_SHOT=doom.ppm \
    build-host/bare_app -p pc-mem
```

## Герои III (VCMI)

Пункт «Герои III» в главном меню (`GAME_HOMM3`, включён в `oga_defconfig`). Игра — клиент
[VCMI](https://vcmi.eu/), открытого движка Heroes of Might and Magic III. Его собирает пакет
`vcmi` SDK (`APPS_CONFIG += bare-app.HOMM3=y`) с патчем связи с bare_app. Данные игры в
образ не входят: файлы оригинальной игры (Shadow of Death или Complete) и моды VCMI
лежат в `GAME_HOMM3_GAME` (`/games/heroes3`: `Data`, `Maps`, `Mp3`, `Mods`, раздел FAT32
SDK, туда копируют с ПК или `scripts/homm3-install.sh` SDK), сохранения и настройки — в
`GAME_HOMM3_DATA` (`/data`). Все моды из `Mods` включены.

- VCMI рисует программно в окно в памяти (видеодрайвер SDL `dummy`) размером вдвое
  больше экрана, 960×640. На экран оно попадает целиком, уменьшенное вдвое, или
  куском 1:1 вокруг курсора («лупа»). L1 переключает режимы.
- Как окно ложится на экран, задаёт `homm3.view` в `game_opts` платформы. `double` (OGA,
  по умолчанию) — как выше. `native`: окно размером с экран, но не меньше 800×600, нужных
  окнам игры (на 854×480 — 854×600), всё 1:1; на экране его часть по положению курсора
  (курсор вверху — верх, внизу — низ), L1 ничего не делает. `fit` (GO Ultra):
  то же окно 854×600 целиком, сжатое по каждой оси отдельно (на 854×480 только по
  высоте), текст рисуется сразу под пиксели экрана; L1 — лупа 1:1 с оригинальными
  шрифтами, как в `native` (переменная `BARE_APP_VCMI_FIT` для VCMI).
- Крестовина в обзоре прокручивает карту приключений, где бы ни был курсор (в других
  окнах — листает списки), в лупе двигает саму лупу; сдвиньте стик, и лупа вернётся
  к курсору.
- У края экрана карта прокручивается, только пока стик наклонён к этому краю: курсор,
  оставленный у края, её не двигает.
- Музыка и звуки идут через alsa-lib на устройство из таблицы платформы.
- Язык игры — язык bare_app (Настройки → Язык): тексты VCMI и модов, а с модом
  перевода (`russian-translation`, его ставит скрипт SDK) и тексты самой игры.
  Смена языка действует с ближайшего запуска игры. Тексты карт и кампаний остаются
  такими, какими их записали: карты русского издания и на английском будут русскими.
- Загрузка с HotA занимает около 10 секунд, всё это время на экране «Загрузка...».
- Если нет VCMI или данных, экран напишет, чего не хватает.

| Кнопка | Действие |
|---|---|
| стик | курсор |
| A | левый клик |
| Y | правый клик (удерживать — подсказка) |
| B | открыть выбранного героя, OK в окнах |
| крестовина | прокрутка карты; в лупе — движение лупы |
| F1 (удерживать) | Ctrl: щелчок по отряду отделяет от него одно существо, как в HotA |
| F2 (удерживать) | Shift: щелчок по отряду делит его поровну на свободные слоты, щелчок по пустому слоту — окно разделения |
| F3 (Select) | отмена (Esc) |
| F4 (Start) | настройки |
| X | конец хода, в бою — автобой |
| R1 | следующий герой, в бою — защита |
| L2 / R2 | громкость тише / громче |
| L1 | обзор / лупа |
| F5 | свернуть игру |
| F5 (удерживать) | монитор системы |
| F6 (удерживать 2 с) | выйти из игры в меню bare_app |

На GO Ultra (`homm3.keys=ogu` в `game_opts`, VCMI получает `BARE_APP_VCMI_KEYS=ogu`)
под экраном ряд F1–F6 и есть второй стик, поэтому там иначе:

| Кнопка | Действие |
|---|---|
| правый стик | то же, что крестовина |
| F1 | свернуть игру (и развернуть) |
| F2 (удерживать) | Ctrl: щелчок по отряду отделяет одно существо |
| F3 (удерживать) | Shift: щелчок по отряду делит его поровну |
| F4 | OK, принять (как B) |
| F5 | на карте приключений — конец хода; в остальных окнах — отмена (Esc, в том числе «Назад» в главном меню) |
| F5 (удерживать) | монитор системы |
| F6 (удерживать 2 с) | выйти из игры в меню bare_app |

Остальные кнопки как в таблице выше; настройки — кнопкой на панели карты.

## Half-Life (Xash3D FWGS)

Пункт «Half-Life» в главном меню (`GAME_HALFLIFE`, включён в `ogu_defconfig` и
`oga_defconfig`). Игра — движок [Xash3D FWGS](https://github.com/FWGS/xash3d-fwgs) с
платформой bare_app (кадры и геймпад через `src/games/game_ipc.h`, звук сам в ALSA) и код
игры hlsdk-portable, из пакетов SDK `xash3d-fwgs` и `hlsdk-portable`
(`APPS_CONFIG += bare-app.HALFLIFE=y`).
Файлы игры в образ не входят: каталог `valve` купленной копии (Steam:
`steamapps/common/Half-Life`) лежит в `GAME_HALFLIFE_GAME` (`/games/halflife`, только
чтение; копирует `scripts/halflife-install.sh` SDK), настройки и сохранения движок
пишет в `GAME_HALFLIFE_DATA` (`/data/halflife`).

- Рендер выбирается в меню игры: «Настройки» → «Видео» (движок хранит выбор в
  `video.cfg`, действует после перезапуска игры). Пока там ничего не выбрано, bare_app
  задаёт рендер платформы: GPU (OpenGL ES, `ref_gles3compat`, если пакет `mesa-panfrost`
  установлен), на OGA программный (Cortex-A35 читает кадры GPU медленнее, чем рисует
  сам), без Mesa программный. `BARE_APP_HALFLIFE_REF` задаёт рендер явно, поверх меню.
- Язык — язык bare_app: движок получает `-language russian` или `english`. Меню по-русски
  берёт строки из `valve_russian` Steam (скрипт копирует и её) и из перевода SDK для
  строк самого Xash; надписи в игре (названия глав, подсказки учебного курса) — из
  перевода SDK `titles_valve_russian.txt`.

| Кнопка | Действие |
|---|---|
| левый стик / правый стик | движение / обзор |
| F1 | меню игры |
| F2 | пауза |
| F3 / F4 | быстрое сохранение / быстрая загрузка |
| F5 | свернуть игру |
| F6 (удерживать 2 с) | выйти из игры в меню bare_app |

Остальные кнопки геймпада и чувствительность — в меню игры: «Настройки» → «Джойстик» /
«Управление».

На ПК: движок собрать с `--64bits --enable-bare-app=<bare_app>/src`, установить в каталог
и задать `BARE_APP_HALFLIFE_PREFIX`, `BARE_APP_HALFLIFE_GAME`, `BARE_APP_HALFLIFE_DATA`.

## SDL2-игры из game.ini

Пункт меню на каждый `<каталог>/<игра>.ini` и `<каталог>/<игра>/game.ini` из
`GAME_NATIVE_DIRS` (`/usr/share/bare_app/games /games`; символ `GAME_NATIVE`). Формат с
комментариями — [docs/game.ini](docs/game.ini): программа, аргументы, что нужно для
запуска, подсказка, раскладка, переменные окружения. Настройки и сохранения игра
пишет в свой каталог `/data/<игра>` (это её HOME).

SDL2-игру не надо менять: SDL2 SDK собран с драйверами `bareapp` (`APPS_CONFIG +=
bare-app.SDL=y`). Окно игры любого размера вписывается в экран с полями, OpenGL ES
рисует GPU. Геймпад приходит как `SDL_GameController`, а для игр без его поддержки
кнопки становятся клавишами по строке `keys`. Пример — Chocolate Doom из Buildroot
(`bare-app.CHOCOLATE_DOOM=y`), у которого есть только
`package/bare-app/games/chocolate-doom.ini` в SDK.

Свернуть игру — F5, выйти — удерживать F6, как в остальных играх.

Как добавить игру любым из способов, с примерами пакета, `game.ini` и записи в реестре:
[docs/GAMES.md](docs/GAMES.md).

На ПК: собрать SDL2 2.32 с патчем SDK (`configure --enable-bareapp`), запускать игру
с этой библиотекой (`LD_LIBRARY_PATH` или rpath) и указать каталог описаний:

```sh
BARE_APP_NATIVE_DIRS=$PWD/my-games BARE_APP_NATIVE_DATA=/tmp/games-data \
    build-host/bare_app -p pc-mem
```

## Состав сборки (Kconfig)

Что входит в бинарник — платформы, драйверы, сервисы, экраны, шрифты, языки,
отладка, — задаёт `Kconfig` (Kconfiglib лежит в `tools/kconfig`, нужен только `python3`).
Готовые наборы в `configs/`:

| defconfig | Для чего |
|---|---|
| `pc_defconfig` | сборка на ПК (по умолчанию): симулятор SDL, `pc-mem`, платформа OGA, тесты |
| `oga_defconfig` | образ OGA (по умолчанию при кросс-сборке и в пакете Buildroot) |
| `ogu_defconfig` | образ ODROID-GO Ultra (платформа `ogu`; можно включить вместе с OGA — выбор по device tree) |
| `oga_minimal_defconfig` | пример урезанной сборки: fbdev, только английский, без слоёв и настроек |

```sh
cmake -S . -B build-host -DBARE_APP_DEFCONFIG=pc_defconfig   # имя из configs/ или путь
make -C build-host menuconfig          # поменять состав; следующая сборка его подхватит
make -C build-host update-defconfig    # сохранить обратно в выбранный defconfig
make -C build-host savedefconfig       # или в build-host/defconfig
BARE_APP_DEFCONFIG=oga_minimal_defconfig tools/oga.sh run    # другой состав на плате
```

`.config` в каталоге сборки пересоздаётся из defconfig, когда тот изменился или выбран
другой. Правки из `menuconfig` живут до этого момента.

## Сборка и запуск

На ПК. Платформа `pc` открывает окно SDL2 (если при сборке был найден `libsdl2-dev`),
`pc-mem` рисует в память — для тестов и сценариев без окна:

```sh
cmake -S . -B build-host && cmake --build build-host -j
cd build-host && ctest                 # юнит-тесты и smoke-тест без тулкита
./bare_app                             # симулятор в окне
echo "down a wait:500 f6" | BARE_APP_SHOT=shot.ppm ./bare_app -p pc-mem   # сценарий кнопок, снимок экрана
BARE_APP_SIZE=854x480 ./bare_app -p pc-mem   # экран другого размера (GO Ultra)
echo stream=1 > s.conf; BARE_APP_CONFIG=s.conf ./bare_app -p pc-mem   # с файлом настроек: здесь стрим
```

На ODROID-GO Advance через консоль (`scripts/oga-serial.py` SDK, плата на `/dev/ttyUSB0`).
Нужен собранный тулчейн прошивки (`make FW=oga rootfs` в SDK):

```sh
tools/oga.sh run            # собрать, скопировать в /tmp/ изменившиеся bare_app и
                            # bare_app_doom, запустить
tools/oga.sh key down a     # нажать кнопки
tools/oga.sh shot s.png     # снимок всех слоёв работающего приложения (SIGUSR1)
tools/oga.sh stop           # остановить, показать конец лога
tools/oga.sh wad doom1.wad  # положить IWAD в /usr/share/games/doom/ (через консоль — минуты)
```

Опции программы: `-p PLATFORM` (без него — по device tree), `-b lvgl|headless`,
`-L en|ru` — язык (или `BARE_APP_LANG`), `-v` — отладочный лог.
На OGA экран выводится через DRM с аппаратными плоскостями (видео под UI, экран «Layers»),
если DRM недоступен — через fbdev. На GO Ultra вторая плоскость принимает только YUV:
видео кладётся под UI процессором, в одну плоскость. Снимок: `kill -USR1 $(pidof bare_app)` → `/tmp/bare_app.ppm`
(или `BARE_APP_SHOT`).
Выход: удержание F6 (`quit_combo` платформы) 2 секунды — пока кнопка нажата, на экране
предупреждение, отпустить раньше — отмена; SIGTERM/SIGINT. Поверх запущенной игры то же
удержание закрывает только игру. Пункт меню «Выход» на платформе
с командой `poweroff` (OGA: `/sbin/poweroff`) после выхода выключает устройство,
на ПК просто закрывает приложение.
Кнопка питания работает везде, и в игре тоже. Короткое нажатие — сон: сначала гаснет
только экран, а другие кнопки перестают действовать; нажатие кнопки питания возвращает
экран. Через 10 секунд с погашенным экраном устройство засыпает по-настоящему командой
`suspend` платформы и просыпается от нажатия кнопки питания; это нажатие не усыпляет
снова. На OGA это `/usr/sbin/pm-suspend` из SDK (сон в RAM, светодиоды гаснут). На GO
Ultra, пока включена настройка «Гибернация» (по умолчанию), — `/usr/sbin/pm-hibernate`:
память пишется в swap-файл на eMMC и устройство выключается совсем, кнопка питания
включает его, и ядро возвращает всё как было, в том числе посреди DOOM 3 (без
swap-файла или если не помещается — suspend to idle); выключенная — сразу
`/usr/sbin/pm-suspend`, suspend to idle: просыпается мгновенно, но батарея тратится. Удержание 2 секунды
выключает устройство, как пункт «Выход»: после полсекунды на экране предупреждение,
отпустить тогда — отмена.

«USB-диск» (`SCREEN_USB_DISK`, команда `usb_disk` платформы, на GO Ultra
`/usr/sbin/usb-disk` из SDK) открывает раздел игр `/games` компьютеру по USB-C, пока
открыт экран: `start` при входе, `status` раз в секунду, `stop` при выходе. Когда
компьютер извлекает диск, раздел возвращается сам и экран говорит, что игры доступны
(A — открыть снова). Пока диск у компьютера, B сначала просит извлечь его там и
закрывает экран только при втором нажатии в течение 3 секунд. Свёрнутую игру пункт
предлагает закрыть: её файлы на этом разделе. На ПК команду подменяет
`BARE_APP_USB_DISK=<скрипт>` (коды выхода: 0 открыт, 2 раздел занят, 3 извлечён,
4 нет компьютера на кабеле).

Шрифты с кириллицей пересоздаются так (нужен Pillow):

```sh
for s in 14 20 28; do tools/gen_font.py --size $s --name ui_font_$s \
    --fallback lv_font_montserrat_$s -o src/gui/view/lvgl/fonts/ui_font_$s.c; done
```

## Настройки

Экран устроен как системные настройки консоли: слева разделы, справа пункты выбранного,
внизу подсказки кнопок. Вверх/вниз — по столбцу, вправо или A — в пункты раздела,
влево или B — обратно к разделам, B в разделах закрывает экран. Ползунок двигается
влево/вправо, выбор (язык, вывод звука) меняется по A.

| Раздел | Пункты |
|---|---|
| Экран | яркость |
| Звук | громкость, вывод звука |
| Интернет | Wi-Fi (открывает экран сетей), IP-адрес |
| Игры | подсказка с кнопками при запуске игры (по умолчанию выключена) |
| Система | язык, дата и время, гибернация (GO Ultra; по умолчанию включена), устройство, платформа, батарея |

Дата и время меняются прямо в строке (если у платформы есть команда `clock`, на GO
Ultra `/usr/sbin/rtc-clock` из SDK; иначе строка только показывает время): A — правка,
влево/вправо — поле (день, месяц, год, часы, минуты), вверх/вниз — значение (по кругу,
день не больше дней в месяце), A — сохранить, B — оставить как было. Часовых поясов нет:
выставленное время и показывается. «Гибернация» выбирает, чем спит устройство: командой
`hibernate` платформы или, выключенная, обычной `suspend` (`hibernate=0` в конфиге).

## Трансляция экрана (RTSP)

Настройки → Интернет → «Трансляция (RTSP)» (символ `STREAM`, в образе GO Ultra
`APPS_CONFIG += bare-app.STREAM=y`). Включённая, она показывает адрес:
`rtsp://<IP>:8554/live`, и сколько зрителей смотрит. Открыть в VLC («Медиа → Открыть
URL»), `ffplay rtsp://…/live`, `mpv rtsp://…/live`; по TCP — `ffplay -rtsp_transport tcp`.

- Картинка — то, что на экране (игра со всем интерфейсом поверх), H.264 854×480,
  30 кадров/с, ~3 Мбит/с. Кодирует аппаратный кодер, если в системе есть
  V4L2-кодер, принимающий XRGB (на GO Ultra — HCODEC, драйвер `meson-venc` SDK:
  ~3,7 мс на кадр, CPU почти не занят; на GO Advance — VEPU2, драйвер
  `rk-vepu-h264` SDK: 960×640 за 8–9 мс); иначе — OpenH264 (BSD) программно
  (~0,8 ядра A73). `BARE_APP_STREAM_SW=1` — программный и при аппаратном. Какой
  выбран, видно в журнале (`h264: … in hardware: /dev/video1 (meson-venc)`).
  Пока никто не смотрит, кадры не собираются и не кодируются.
- Игра, которая рисует больше экрана и уменьшает картинку под него, отдаёт
  трансляции свою картинку целиком (`game_ipc.h`: «собственная картинка игры»), и
  трансляция идёт в её разрешении (до 1920×1088 — предел обоих аппаратных
  кодеров), без интерфейса bare_app поверх: Герои III (VCMI) — 1708×960 на GO Ultra
  в обычном виде, 960×640 на GO Advance; Windows-игры — экран Windows как есть, с
  курсором (Pirates! и Daemonica — 800×600, HotA — 854×600); SDL-игры, чьё окно
  больше экрана, — окно как есть (с `SDL_BAREAPP_GL_ASYNC`, пока трансляция его
  просит, GPU копирует окно без уменьшения, уменьшает CPU). Игры, рисующие прямо в
  размер экрана (Half-Life, DOOM 3, Doom), транслируются в размере экрана.
- Звук — то, что играют игры, L16 48 кГц стерео (~1,5 Мбит/с). Пока трансляция
  включена, игры, запущенные после включения, играют в ALSA loopback (`snd-aloop`,
  bare_app загружает модуль сам), трансляция берёт звук оттуда и передаёт дальше на
  устройство. Игра, запущенная до включения, звучит только на устройстве.
- RTP по UDP (порты сервера 6970–6975) или внутри соединения RTSP (TCP); RTCP-отчёты
  отправителя раз в 2 с, по ним плеер сводит звук с картинкой. До 4 зрителей.
- VLC из Debian/Ubuntu собран без live555 и открывает `rtsp://` модулем SAT>IP: тот
  не спрашивает описание потока и ждёт внутри RTP поток MPEG-TS. Такому зрителю
  (SETUP на сам адрес, без `track1`/`track2`) трансляция отдаёт MPEG-TS по RTP:
  то же H.264 и звук как Blu-ray LPCM. Остальные плееры получают отдельные дорожки,
  как раньше.
- Нагрузка на GO Ultra: около 0,8 ядра A73 на сборку кадра и кодирование.

## Звук и Wi-Fi

В настройках: громкость, вывод звука (авто — по штекеру наушников, динамик,
наушники), строка Wi-Fi открывает экран сетей: вкл/выкл, состояние и адрес, сети
рядом, подключение (ключ новой сети вводится на экранной клавиатуре) и «забыть».
Громкость, вывод и вкл/выкл Wi-Fi хранятся в файле настроек. При смене громкости
звучит короткий сигнал новой громкости (`SOUND_FEEDBACK`).

- Звук — ioctl управляющего устройства ALSA (`/dev/snd/controlC0`), без alsa-lib.
  Имена регуляторов задаёт таблица платформы. У кодека OGA (rk817) выход сам по
  штекеру не переключается, это делает `bare_app` в режиме «авто». Сигнал громкости
  выводится через ioctl устройства PCM; устройство освобождается через секунду
  после сигнала, чтобы его мог взять Doom.
- Wi-Fi — управляющий сокет работающего `wpa_supplicant` (как у `wpa_cli`, без
  libwpa_client). Сети и ключи хранит он сам (`update_config=1`). Адрес получает
  системный DHCP-клиент: в образе OGA его перезапускает `/etc/wpa_cli.action` при
  подключении к другой сети. Новый ключ сначала проверяется отдельной записью, так
  что опечатка не портит сохранённую сеть.
- На ПК (`pc`, `pc-mem`) оба устройства — имитация (`src/drivers/sim.c`): несколько
  выдуманных сетей, верный ключ — любой от 8 символов, начинающийся с `pass`.

## Управление

| Кнопка | Действие |
|---|---|
| крестовина / стик вверх-вниз | перемещение фокуса |
| влево / вправо | значение у виджета в фокусе (ползунок) |
| A | нажать |
| B | назад (на экране теста ввода — дважды) |
| L1 / R1 | предыдущий / следующий виджет |
| X | второе действие: управление игры на её плитке, забыть сеть Wi-Fi (дважды), стереть символ на экранной клавиатуре |
| L2 / R2 | громкость тише / громче (кроме теста ввода) |
| громкость + / − | громкость с любого экрана, и в игре (если у платы есть эти кнопки; у OGA Black Edition их нет) |
| питание (коротко) | сон: экран гаснет, через 10 с настоящий сон; вернуть экран / проснуться |
| питание (удерживать 2 с) | выключить |
| F5 | развернуть свёрнутую игру (Героев III на GO Ultra — и F1) |
| F5 (удерживать 0,6 с) | показать / спрятать монитор системы, и в игре |
| F6 (удерживать 2 с) | выход (в игре — выход из игры) |

На экранной клавиатуре крестовина ходит по клавишам, A печатает, ✓ подключает.

USB-клавиатура и мышь (символ `INPUT_HID`, драйвер `drivers/input_hid.c`): любые,
подключённые в любой момент; устройства захватываются (`EVIOCGRAB`), иначе клавиши
попадали бы и в текстовую консоль (Alt+F2 увёл бы экран). В меню и в играх без своей
клавиатуры стрелки — крестовина, Enter — A, Esc и Backspace — B, Space — X, Tab — Y,
Page Up/Down — L1/R1, F1…F6 — те же кнопки. Windows-играм (`bare_app_wine`),
Heroes III и Half-Life клавиши идут как есть: `GAME_MSG_KEY` с кодом клавиши Linux
(горячие клавиши, назначение клавиш, ввод текста), их получает только игра, запущенная
с `game_spawn.keyboard`.
Мышь (`GAME_MSG_MOUSE_BUTTON`, `GAME_MSG_MOUSE_MOVE`, `game_ipc.h`) получают игры с
`game_spawn.mouse`: Windows-игры, Heroes III, Half-Life (обзор в игре, курсор в меню),
Doom (поворот, кнопки — огонь, стрейф, вперёд, колесо — следующее оружие) и
SDL-игры из game.ini (драйвер SDL bareapp, относительный режим тоже). Отпускание
всегда идёт туда же, куда нажатие.

### Датчик движения (прицел гироскопом)

USB-датчик движения (проект usb_motion_sensor: какой-нибудь IMU на Pico, USB-serial
1209:0001 «USB Motion Sensor», символ `INPUT_IMU`, драйвер `drivers/input_imu.c`):
найден по USB id в любой момент подключения (`/dev/ttyACMn`, ядру нужен `cdc_acm`).
bare_app не знает, какой чип стоит в датчике: всё о нём приходит в `PKT_INFO` протокола v3
(прошивка 0.2 и новее, другие не читаются, в журнале — просьба обновить): имя, какие
каналы есть (гироскоп, акселерометр, магнитометр, температура), частота, масштабы в °/с и
g на отсчёт, шум гироскопа и акселерометра. Канал без масштаба считается отсутствующим.
Сэмплы идут пачками до 4 в USB-пакете, `poll()` будит на целую пачку
(VMIN = длина её кадра; 1, пока сэмплы не идут, чтобы статус приходил сразу).
Период сэмпла измеряется по часам датчика, окнами по 0,25 с (и не меньше 8 интервалов
между сэмплами со своей меткой времени — первыми в пачке; номера в интервале считаются
все, и потерянные). В окне считаются интервалы не дальше 0,5 мс (дрожание меток:
прошивка опрашивает датчик) от медианы их периодов, а опоздавшая метка — вместе со
следующим интервалом, если он её покрывает; не считается то, что ничем не покрыто, —
пауза — и частота, отличная от большинства в окне. Период — всё время на все сэмплы
последних 8 окон одной частоты (2 с: дрожание меток делится на всё это время, а окно,
укороченное паузой или потерей, весит мало); окно, отличающееся от них больше чем на
2 %, начинает период заново — частота сменилась. На настоящем датчике первое окно не
дальше 0,15 % от точного, через секунду — 0,05 %, пауза и потеря в любом месте этого не
меняют. Берётся в пределах 0.5…2× от заявленной, за ними — снова заявленная. «Не та»
частота после подключения или сменившаяся без `PKT_INFO` (прошивка так не делает)
учитывается за два окна (у датчика медленнее ~32 Гц окно — 8 интервалов, после смены —
до 16). Разрыв внутри потока замер не сбрасывает (новый порт меряет заново).
Повторённый кадр (первый номер — среди номеров прошлого кадра) пропускается. Пока замера нет,
паузой по меткам времени считается только то, что сверх худшего случая — вдвое длиннее
заявленного периода, — в таких периодах: целая пачка при вдвое меньшей частоте паузой
не выглядит, а пауза в десятки периодов — да. В журнал частота пишется один раз для
каждого `PKT_INFO` и снова при каждой смене «принята»/«отвергнута». Датчик опознаётся как
`<имя>-<USB serial>` сразу по `PKT_INFO`, до его сэмплов: у каждого своя калибровка, другой
датчик (или другие каналы) начинает с нуля. От шума из `PKT_INFO` считаются пороги: «лежит
неподвижно» — 4× шум гироскопа (0.3…1.5 °/с) и 4× шум акселерометра (0.003…0.03 g),
сглаживание — 25× шум гироскопа (2…8 °/с), подавление остатка нуля — 2× (0.1…0.6 °/с);
шум неизвестен — 0.6 °/с, 0.01 g, 4 °/с, 0.3 °/с.
Гироскоп поворачивает обзор игры как мышь: `core/motion.c` переводит его в
градусы поворота вправо и вниз, экран игры умножает их на «отсчёты мыши на градус»
игры (`game_def.gyro_counts`, в game.ini — `gyro = 9.09`) и чувствительность её
управления и шлёт `GAME_MSG_MOUSE_MOVE` (доли отсчёта копятся).

- Ноль гироскопа плывёт с температурой: он измеряется сам, когда консоль лежит
  неподвижно секунду (разброс меньше порога), и калибровкой.
- Влево-вправо — поворот вокруг вертикали мира (по гравитации, акселерометр с
  комплементарным фильтром), как бы ни была наклонена консоль и как бы ни стоял датчик.
- Вверх-вниз — поворот вокруг оси консоли «влево-вправо», которую знает только
  калибровка (как закреплён датчик); без неё работает только влево-вправо.
  Верхний край к себе — взгляд вниз, от себя — вверх.
- Малые повороты (дрожь рук) сглаживаются за 40 мс, большие идут как есть.
- Магнитометр для прицела не нужен: без него всё работает.
- Без акселерометра гравитации нет: влево-вправо — поворот вокруг вертикали самой
  консоли, которую тоже находит калибровка (шаг «поверните влево»); до калибровки прицел
  не работает, неподвижность — по одному гироскопу.
- Без гироскопа скорость поворота считается по повороту гравитации: акселерометр
  сглаживается, затем усредняется за окно, которое тем дольше, чем он шумнее (45 с на g
  шума, приведённого к 1139 Гц по частоте из `PKT_INFO`, 30…120 мс: у шума 0,0022 g на
  1,1 кГц — 0,1 с), и «гироскоп» — поворот этого среднего от сэмпла к сэмплу (угол через
  atan2): такие повороты складываются в весь поворот при любых шагах и любом угле за шаг;
  на настоящем датчике в покое 0,29 °/с rms; вверх-вниз (после калибровки) работает, поворот вокруг вертикали
  акселерометр не видит — влево-вправо нет. Ноля у такого «гироскопа» нет: в калибровке
  шаг «на стол» пропускается.
- Разрыв потока решает только разборщик (`drivers/input_imu.c`), одним правилом: первый
  сэмпл потока (новый порт, новая частота) или больше 3,5 пропущенных сэмплов, считая
  вместе пропущенные по номерам и по меткам времени (пауза при сплошных номерах —
  прошивка переподключила свой датчик). После разрыва сэмпл считается за один период, и
  устаревает то, что держится на непрерывности потока: «гироскоп» из гравитации и оценка
  «верха» (берётся заново с первого сэмпла акселерометра в 0,3…3 g, до него поворота
  нет). Поворот за разрыв в обзор не попадает ни с гироскопом, ни без, и поворот сразу
  после разрыва идёт вокруг настоящей вертикали. То, что сэмплы до разрыва показали, не
  теряется: ни ещё не взятое игрой, ни хвост сглаживания; окно неподвижности тоже
  остаётся (каждый его сэмпл был неподвижен или нет сам по себе: ноль гироскопа
  меряется и через разрыв). Переподключение того же датчика — такой же разрыв: ни его
  ноль, ни окно неподвижности не сбрасываются. Без гироскопа при разрыве теряется часть наклона, которую
  самодельный гироскоп ещё не отдал (её не отличить от толчка): от резкого наклона
  (за ~0,1 с) сразу после него — почти весь, от наклона за 1 с — 14…18 %; через 0,3 с
  после наклона — не больше 15 %, через 0,5 с — около 3 % (цифры для датчика от 104 Гц).
  До 3 пропущенных — не разрыв: сэмпл считается за
  пропущенные по номерам шаги (гироскоп — с его скоростью), акселерометр видит наклон за
  них; пауза по времени шагов не добавляет (сэмплов в ней не было: прошивка
  перезапускала датчик или не успела его прочесть), поворот за неё неизвестен. Проверено
  матрицей `test_motion_matrix` (режимы × 1, 5, 104, 1000 Гц × события, пачки как у
  прошивки, частота датчика и не та, что заявлена).
- Медленный датчик (секунды между сэмплами): ровный поворот медленнее 2 °/с дольше
  секунды для него неотличим от нуля гироскопа и им и становится.
- Ни гироскопа, ни акселерометра: прицела нет, экран датчика так и пишет.

Без датчика можно проверить на FAKE: `printf F > /dev/ttyACM0` переключает прошивку на
синтетический датчик (833 Гц, повороты и наклон по сценарию), `A` и `G` — он же без
акселерометра и без гироскопа, `r` — обратно к настоящему.

Настройки → Игры → «Датчик движения» (справа — «Подкл.»/«Откл.», меняется сразу при
подключении и отключении): общие для всех игр «Чувствительность» (0.2…5.0×, по
умолчанию 1.0×; умножается на чувствительность из управления игры), «Инверсия X» и
«Инверсия Y» (вверх/вниз — строка, влево/вправо — значение, сохраняются при выходе с
экрана строками `gyro.sensitivity`, `gyro.invert_x`, `gyro.invert_y` в
`bare_app_sticks.conf`); подключён ли датчик, его имя и частота, чего у него нет, измерен
ли ноль, откалиброван ли он, и крестик, который следует за поворотами консоли.
A — калибровка: положить консоль на стол (1,5 с, ноль гироскопа; без гироскопа этого
шага нет), потом взять как в
игре, подержать и наклонить верхним краем к себе на 25° (ось «вправо»), без
акселерометра — ещё повернуть влево на 25° (вертикаль); результат сохраняется в
`bare_app_sticks.conf` строкой `gyro.<датчик> = bias x y z right x y z [up x y z]`.
X — крестик в центр, Y — удалить калибровку.

В строке статуса, пока подключено хоть что-то из USB-клавиатуры, мыши и датчика
движения, — один значок USB (значки справа идут через 8 px; если они дотянутся до
часов, часы встают левее них, а не по центру). Драйверы сообщают устройства в `core/input`
(`input_report_devices()`), view пересылает маску в control (`ACT_INPUT_DEVICES`),
тот кладёт её в контекст (`CTX_INPUT`, `ctx.input.devices`).

В симуляторе SDL: стрелки, X = A, Z/Esc = B, S = X, A = Y, Q/W = L1/R1, 1…6 = F1…F6.
